# Google ↔ Outlook 同期の動作仕様

## 1. 概要

この同期処理は Google Apps Script で動作し、Google カレンダーと Outlook カレンダーの予定を双方向で同期します。

同期の起点は `syncCalendars()` です。30 分間隔で `installThirtyMinuteTrigger()` を設定して実行します。

全処理は UTC を基準に統一し、内部ではすべて UTC 時間で扱います。

## 2. 同期ウィンドウと処理フロー

### ウィンドウ

毎回次の範囲を対象にします。

- 開始: 実行時点の現在時刻
- 終了: 現在時刻から 1 か月後の当日 23:59:59.999

つまり、実行時点を起点にした前方 1 か月の範囲です。

### 処理の全体フロー

データ準備から同期実行まで、次の順序で進みます。

1. **データ準備**: Google と Outlook から同期ウィンドウ内のイベントを取得・正規化（繰り返しイベント展開含む）
2. **繰り返しイベント比較処理**: 繰り返し予定を各 occurrence 単位で比較、更新判定
3. **繰り返しイベント同期処理**: 繰り返し occurrence の作成・更新・削除を実行
4. **一般イベント比較処理**: 単一イベントを比較、更新判定
5. **一般イベント同期処理**: 単一イベントの作成・更新・削除を実行

## 3. 取得フロー

### Google 側

`getGoogleEvents(startDate, endDate)` で既定カレンダーを取得します。

- `Calendar.Events.list()` を使う
- `singleEvents: true` を指定する
- `orderBy: 'startTime'` を使う
- `timeMin` / `timeMax` は RFC3339 with offset (+09:00) で送る
- 取得後に同期ウィンドウとの重なりで再フィルタする

### Outlook 側

`getOutlookEvents(startDate, endDate)` で取得します。

- Microsoft Graph API の `calendarView` を使う
- `startDateTime` / `endDateTime` を指定して取得する
- 取得後に同期ウィンドウとの重なりで再フィルタする

## 4. 同期キー（syncKey）

イベントの対応付けは occurrence 単位で行います。

syncKey は次の形式です。必ず `google_id:` または `outlook_id:` で始まります。

### Google イベント

- **単一イベント**: `google_id:<eventId>`
- **繰り返し occurrence**: `google_id:repeat_<recurringEventId>_<occurrenceDateTime>`
  - `eventId`: Google Calendar API のイベントID
  - `recurringEventId`: Google Calendar API の繰り返しイベント ID
  - `occurrenceDateTime`: occurrence の元の開始時刻（UTC、RFC3339 形式）

### Outlook イベント

- **単一イベント**: `outlook_id:<eventId>`
- **繰り返し occurrence**: `outlook_id:repeat_<recurringEventId>_<occurrenceDateTime>`
  - `eventId`: Graph API のイベントID
  - `recurringEventId`: Graph API の繰り返しイベント ID
  - `occurrenceDateTime`: occurrence の開始日時（UTC、RFC3339 形式）

### description 内のメタデータ

description には同期キーと互換用の補助情報が入ります。

- `google_id:` - Google イベント ID（単一の場合）
- `outlook_id:` - Outlook イベント ID（単一の場合）

## 5. ID 記載ルールと作成元判定

### Google カレンダー側の判定

- **`outlook_id:` が概要欄にない** → Google カレンダーで作成されたイベント
- **`outlook_id:` が概要欄にある** → 過去に Outlook カレンダーから同期されてきたイベント

### Outlook カレンダー側の判定

- **`google_id:` が概要欄にない** → Outlook カレンダーで作成されたイベント
- **`google_id:` が概要欄にある** → 過去に Google カレンダーから同期されてきたイベント

### ID 厳密化を行う理由

同期したイベントにイベントIDを設定することで、「重複して同期してしまう事」や「過去に同期したイベントが作成元カレンダーに戻ってしまう事」を防止することが出来ます。例えば、Google カレンダーにユーザーが作成したイベントを Outlook へ同期する際に、概要欄にGoogleカレンダーにのイベントの `google_id:` を追加することにより、次回実行時にこのイベントを誤ってこのイベントをGoogleカレンダーに同期してしまう事を防ぐ。

### ID 取得方法の統一ルール

google_id や outlook_id などの取得方法は、コード内で統一します。

**Google イベント ID**:
- `htmlLink` から `eid=` パラメータを抽出する方法のみを使用
- 実装例は [Google 側実装仕様](Google仕様書.md#イベント-id-の取得) を参照

**Outlook イベント ID**:
- Graph API の `id` フィールドを使用
- 実装例は [Outlook 側実装仕様](outlook仕様書.md#イベント-id-の取得) を参照

統一された取得方法により、同期処理全体で ID の形式と信頼性が保証されます。

## 6. 同期処理

### Google → Outlook

`buildGoogleToOutlookSyncTasks()` でタスクを作成し、`runGoogleToOutlookTasks()` で実行します。

- Google の syncKey が概要欄に含まれているイベントがoutlookカレンダーに見つかれば、そのイベントを更新
- 見つからなければ作成
- Google の syncKeyが概要欄に含まれているのに、そのキーがGoogleカレンダーに存在しない場合（Googleカレンダーからイベントが削除された場合）は削除

### Outlook → Google

`buildOutlookToGoogleSyncTasks()` でタスクを作成し、`runOutlookToGoogleTasks()` で実行します。

- outlook の syncKey が概要欄に含まれているイベントがgoogleカレンダーに見つかれば、そのイベントを更新
- 見つからなければ作成
- Outlook の syncKeyが概要欄に含まれているのに、そのキーがOutlookカレンダーに存在しない場合（Outlookカレンダーからイベントが削除された場合）は削除

## 7. 更新と削除

現在の実装は、更新だけでなく削除も行います。

- `deleteOutlookEvent()` は Google → Outlook 側で使う
- `deleteGoogleEvent()` は Outlook → Google 側で使う

タスクは `delete → update → create` の順に処理します。

## 8. イベントの比較と更新判定

### 比較項目

イベントが作成や更新かを判断するため、以下の項目を新旧で抽出して比較します。

- タイトル
- 開始・終了日時
- 終日フラグ（新旧共に終日イベントの場合は、開始・終了時刻は無視して良く、開始・終了日のみの比較で良い）
- 場所
- 表示状態
- 公開度や機密度
- 空き状況（free / busy）
- recurrence 情報

上記のいずれか一つでも変更があれば更新対象とします。

### イベントが作成か更新かの決定

作成対象か更新対象化を確認したいイベントの同期キーを取得し、それが既存のイベントの中に、それが概要欄に含まれているものがあるかどうかで決まります。

- **見つかった** → 更新対象（比較項目に変更があれば更新）
- **見つからない** → 作成対象

## 10. 繰り返しイベント処理

### ポリシー

繰り返しイベントは Microsoft Graph API の繰り返し定義に沿って内部処理を行います。

- **繰り返し定義の取得**: Graph API の `recurrence` オブジェクトを読み込む
- **例外イベントを反映**: `seriesMasterId` などの関係情報を使って occurrence へ反映
- **同期ウィンドウ内 occurrence を評価**: 対象範囲の occurrence を比較対象にする

### 同期登録

繰り返しイベントを Google / Outlook へ登録する時は、Graph API の `recurrence` 情報を基にイベントを登録します。

- **Google への登録**: `recurrence` 配列を物供
- **Outlook への登録**: `recurrence` オブジェクトを物供

### 繰り返しイベント全体が更新された場合の同期

繰り返しイベント（マスターイベント）が全体的に更新された場合、その開始日が同期ウィンドウ（「今日から1ヶ月」）の外にあっても、そのイベント全体を更新します。

これにより、過去に作成された繰り返しイベントに対する編集（例：繰り返し条件の変更、タイトル変更）を確実に反映することができます。

## 11. ログ
- **Google API**
  - クエリパラメータ (`timeMin` / `timeMax`): UTC ベースの RFC3339 with offset (+09:00)
  - 取得イベント: RFC3339 with offset の形式
  - 送信イベント: RFC3339 with offset の形式

- **Outlook Graph API**
  - クエリパラメータ (`startDateTime` / `endDateTime`): UTC 基準の ISO 文字列
  - 送信イベント: `dateTime` + `timeZone` の分離形式

すべてのイベントは以下の様にイベント内容を扱います。

| 項目名 | Google | 内部表現 | Outlook |
| ----- | ------ | ------- | ------- |
| イベントID |  | eventData.id | eventData.id  |

 ### `showAs` の扱い

- Graph API の `sensitivity` を内部表現に保持する
- 同期時は Google 側の `visibility` と相互変換する

### 結果のログ

個別の結果は `logAction()` でコンソールに出します。なお、<イベント名>は同期するイベント名に置き換え、<同期方向>は、「google->outlook」または「outlook->google」を使用してください。

- <イベント名> を <同期方向> に作成しました
- <イベント名> を <同期方向> に更新しました
- <イベント名> を <同期方向> に削除しました

集計は `outputSummaryLog()` で次の形式に出します。

- Google → Outlook の作成・更新・削除件数
- Outlook → Google の作成・更新・削除件数

## 12. 実行・認証

### Google 側

Google Calendar の Advanced Service と OAuth scope を使います。`appsscript.json` では Calendar API と external request が有効です。

### Outlook 側

`outlookOauth2.gs` で PKCE を使った OAuth2 認証を行います。

- `setup()` で認可 URL を作る
- `authCallback()` で token を保存する
- `refreshAccessToken()` で自動更新する

## 13. Script Properties

現在の実装で必要な主な値は次の通りです。

- `CLIENT_ID`
- `TENANT_ID`
- `OUTLOOK_CALENDAR_ID`
- `AUTH_CODE`
- `OUTLOOK_CODE_VERIFIER`
- `REFRESH_TOKEN`
- `ACCESS_TOKEN`

## 14. 留意事項

- 同期の開始点は日始まりではなく実行時点です
- 同期ウィンドウの範囲内において、同期元のカレンダーでイベントが削除されると、同期先のカレンダーでも削除されます。
- 認証トークンなどの機密情報は Logger に出力してはいけません。
- このドキュメントを含むすべてのドキュメントに書かれた関数は一例であり、実装上必要な関数は任意で作成・編集・削除してください。ただし、それらの変更は原則googleとoutlookの仕様書に反映させてください。
- 各関数は、以下の形式で関数の解説を付けてください。
